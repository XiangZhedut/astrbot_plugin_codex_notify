# Codex 交互与通知助手

**在手机 QQ 上继续 Codex 工作：引用任务通知向指定聊天下发指令，或通过口令新建 Codex 聊天。** 同时接收完成、运行受阻、待回复和账户额度提醒。

面向 **Windows、AstrBot 与 Codex 桌面同机运行**。远控属于实验性第三方集成，依赖 Codex 桌面内部工具接口，**不是 OpenAI 官方插件，也不是公开 OpenAI API 集成**。桌面版本或记录格式变化可能使功能失效。

## 功能

- **引用通知续聊 Codex**：通过已登记的随机回复标记定位聊天，不根据窗口焦点或聊天名称猜测。
- **口令新建 Codex 聊天**：绑定用户发送 `/新建Codex 口令 任务指令`，创建独立的本地无项目聊天。
- **身份和频率控制**：只允许绑定用户在原绑定会话操作；新建和续聊共用发送间隔，默认10秒；消息去重，结果不明时不自动重发。
- **运行中发送开关**：默认拒绝；开启后由桌面原生接口处理追加或排队，不主动中断任务。
- **任务与额度通知**：完成、失败、容量不足、明确中断、可识别的待回复请求、额度预计重置提醒；过滤内部标题、建议和子代理任务。
- **当前额度与可选上下文**：显示最近记录的剩余量和重置时间；可选择让 BOT 在后续对话中参考已发送通知。

## 环境与验证范围

| 项目 | 范围 |
| --- | --- |
| 系统 | Windows；远控使用本地 Windows 命名管道 |
| AstrBot | 声明 `>=4.29.3,<5`，实际测试4.29.3 |
| Python | 当前测试环境3.12 |
| Codex | 当前验证桌面捆绑 CLI `0.165.0-alpha.1.2`，依赖其 `codex-app-tools`、`state_5.sqlite` 和 JSONL 格式 |
| 消息平台 | QQ 官方适配器；引用续聊已在作者环境实测 |
| 数据目录 | 同一系统用户的标准 `~/.astrbot/data` 与 `~/.codex` |

适配器必须提供引用正文和稳定消息ID。其他适配器、Linux/macOS、Docker、异机部署、自定义数据目录及所有QQ消息类型未完整验证，不声明全面兼容。新建等功能有模拟测试，不将其描述为所有环境全链路实测。

## 安装与接入

1. 从插件市场/仓库安装，或在 AstrBot 插件页上传发行 ZIP。
2. 保持同机 Codex 桌面运行并正常登录。插件不会索取或保存 OpenAI 密码、API密钥、登录认证令牌。
3. 先备份 Codex 全局 `~/.codex/config.toml`，将 `notify` 指向安装目录内的发送脚本，替换为自己的实际路径：

   ```toml
   notify = ["C:\\path\\to\\python.exe", "C:\\path\\to\\AstrBot\\data\\plugins\\astrbot_plugin_codex_notify\\tools\\codex_astrbot_notify.py"]
   ```

   如已有自定义 notify，应先自行合并。脚本兼容 UTF-8 BOM，并尝试保留本机已有 Codex 桌面 `turn-ended` 处理器；该辅助处理器也与桌面版本相关。

4. 在 Codex 中完成一次简单回复，建立/刷新桌面连接描述。未加载新 notify 时，等工作结束后重启 Codex 再试。
5. 在 QQ 目标私聊或群聊发送 `绑定CODEX通知到当前会话`；按提示在 AstrBot 插件配置页查看4位验证码，由发起人在同一会话回复验证码。
6. 按需要开启远程回复/新建功能并设置口令。远控开关及运行中发送默认关闭。

验证码默认5分钟有效、最多3次尝试；新的绑定会使旧验证码失效。若平台只转发被提及消息，请 @机器人。管理员命令包括 `/Codex通知 绑定`、`状态`、`测试`、`解绑`。

## QQ 交互用法

### 引用续聊

开启“开启 Codex 回复”，等待收到带 `【Codex回复标记：…】` 的新通知，**引用整条通知**输入指令。没有标记的旧通知、未登记标记、跨会话引用、缺失消息ID或无法确认目标状态时不发送。若平台不提供引用正文，无法识别目标，不回退当前窗口。

### 新建聊天

开启“开启 Codex 窗口新建”，设置非空且不含空格的口令，发送：

```text
/新建Codex 你的口令 帮我分析这个任务
```

口令支持中文，不替代身份验证。成功确认消息附带回复标记。插件不指定模型、不额外扩大权限，仍由当前桌面设置和指令决定执行行为。

### 权限、间隔与运行中发送

验证码/管理员绑定会记录绑定者身份。已有QQ官方私聊绑定可按绑定私聊身份校验；群聊旧绑定没有绑定者信息时需重新验证。绑定变更不继承原身份。

新建和续聊**共用绑定用户的发送间隔**，默认10秒，范围1～3600秒。运行中发送默认关闭；开启后使用桌面原生发送接口追加或排队，不保证立即进入当前轮次。不能从 QQ 代替桌面批准权限弹窗。

接口超时或回执不明时，先回桌面核实。插件记住本条消息，不自动重放；换一条新消息重试仍可能重复执行，请先确认。

## 通知设置

| 设置 | 行为 |
| --- | --- |
| 完成提示/任务名/任务地址/结果 | 可独立选择完成通知内容 |
| 回复包含：当前额度 | 默认开启，显示最近快照的剩余量和北京时间重置时间 |
| BOT 上下文可见 Codex 通知 | 默认关闭；开启后提供当前会话最近8条、24小时内的通知，每条最多2400字 |
| 最终回复完成后的发送缓冲 | 默认10秒，范围0～120秒，缓解桌面显示延迟 |

格式示例（非实时账户数据）：`当前额度（剩余，最近记录）：72%/5小时 13:58，66%/周 11-04 15:11`。

剩余量为 `100 - used_percent`，不是聊天上下文剩余 token。未取得数据时显示未知/暂无记录；到期未刷新显示待刷新，不推断已恢复100%。额度到点仅提示**预计重置时间已到**，实际以 Codex 面板为准。

插件每两秒增量读取用户聊天记录，可覆盖 Windows 通知参数过长（错误206）导致的漏发。首次从已有记录末尾开始，不补发所有历史；重启后继续检查点。默认完成通知约10～12秒，异常/待回复/额度约2～4秒，但不能保证与界面最后一个字同步。

仅可识别记录会产生提醒。只在桌面实时通道显示、未落盘的弹窗可能漏报；最终答复末尾的明确提问属于保守文本判断，可能误判；不把无输出或仍在自行修复的工具错误猜测为暂停。

## 数据、网络与权限

- **读取**：当前用户的 Codex 聊天索引、JSONL完成记录、额度快照和桌面提供的工具管道地址。不读取 `auth.json`、提取登录密钥或修改 Codex 会话数据库。
- **保存**：插件数据目录中的绑定身份、随机桥接令牌、连接描述、回复映射、消息去重、发送队列和检查点。队列可能暂存正文，成功后清除队列正文；上下文功能另保留有界摘要。
- **发送**：通知正文经所选消息平台发送到绑定聊天；QQ指令送入本机 Codex，由当前 Codex 账户服务处理。**开启 BOT 上下文功能后，通知摘要还会随后续 BOT 请求发送给 AstrBot 配置的模型服务。** 不要绑定不可信群聊。
- **监听**：通知桥只允许回环地址（默认 `127.0.0.1:6198`），需随机令牌，无作者运营的远程服务，不对公网开放远控端口。
- **进程**：远控使用当前 Python 启动短生命周期工作进程，15秒超时；不拼接 shell 命令，不启动第二个 App Server，不下载/分发 Codex 或 QQ 可执行文件。
- **日志**：记录时间、事件类型、聊天/轮次标识及投递状态，不主动记录指令正文、口令或桥接令牌。

关闭开关不自动删除本地历史。需要清理时可在退出 AstrBot 后删除本插件数据目录，请自行保留所需数据。不要公开上传运行目录、数据库、配置或连接描述。

## 连接与故障排查

桌面工具命名管道**不是稳定公开 SDK**。重启或更新可能使连接失效；先完成一次正常用户聊天回复刷新连接，再检查 `~/.codex/astrbot-notify.log`。`notify_received` 为脚本触发，`astrbot_queued` 为排队，`astrbot_delivered` 为 AstrBot 发送接口返回成功，非平台客户端展示的独立确认。

本项目不声称 OpenAI、腾讯或 AstrBot 官方背书。使用者应遵守对应平台条款。实验接口的可分发性与商店上架资格仍需维护者审核，技术测试通过不等于合规批准。

## 开发测试

依赖 Python 标准库和 AstrBot 已提供的 `aiohttp`，无需捆绑第三方包。在安装对应 AstrBot 开发依赖的环境中，从仓库父目录执行：

```powershell
python -m unittest discover -s .\astrbot_plugin_codex_notify\tests -v
```

测试使用临时数据库和模拟接口，不发送真实工作指令。QQ引用续聊另由用户实际测试成功。
